# 작업예정 — 아직 안 한 일

## 한눈에

| 폴더 | 무엇 |
|---|---|
| `작업예정/rough_files/` | 받은 자료 원본 (지시, 녹음 받아쓰기, 메일, HTML) |
| `작업예정/` | **아직 시작 안 한 일.** 일 하나 = 파일 하나 |
| `진행사항/` | **시작했거나 끝난 일.** 같은 파일을 옮겨 와서 결과를 이어 씀 |

파일이 어디에 있는지가 곧 그 일의 상태다.

## 쓰는 법

1. 받은 자료는 먼저 `rough_files/`에 넣는다.
2. 그걸 보고 할 일을 나눠 이 폴더에 파일 하나씩 만든다. 크기는 "끝 조건으로 끝났는지 확인할 수 있는 한 가지 목표". 파일 이름에 날짜를 넣지 않는다.
3. 할 일 파일에는 네 가지를 적는다.
   - 출처: `rough_files/` 파일 이름과 녹음 시각 (예: `…_2.txt` 04:56~06:33)
   - 왜
   - 할 일: 체크 목록 (`- [ ]`)
   - 끝 조건: 무엇을 확인하면 끝인지
4. 시작하는 날, 그 파일을 `진행사항/`으로 **옮기고** 이름 앞에 시작 날짜를 붙인다. 결과는 같은 파일 아래에 이어 쓰고, 한 일은 체크한다.
5. 끝나도 `진행사항/`에 그대로 둔다.
6. 할 일 목록은 **이 README에만** 둔다. 진행사항 문서 안에 적힌 "할 일"은 그날의 기록이다.

## rough_files 규칙

- 받은 그대로 둔다. 내용이 틀려도(예: 녹음의 화자 표시가 바뀜) 원본은 고치지 않고, 할 일 파일에 적는다.
- 파일 이름 앞에 받은 날짜를 붙인다: `2026-11-11_이름.txt`
- 다 쓴 뒤에도 지우지 않는다. 진행사항 문서가 근거로 가리킨다.
- 내용이 모두 할 일 파일로 나뉘었거나 안 하기로 정했으면 `rough_files/done/`으로 옮긴다.
  옮길 때 그 파일을 가리키는 경로도 함께 고친다.
  그래서 `rough_files/` 바로 밑에는 "아직 할 일로 안 나눈 자료"만 남는다.
