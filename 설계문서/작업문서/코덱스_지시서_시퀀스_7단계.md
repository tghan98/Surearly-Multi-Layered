## 2. 할 일

### 2-1. 7단계 이식

`APP_CTRL_Sequence_Process()`의 `/* NOT YET PORTED */` 블록을 지우고,
아래 7개를 각각 `s_Step<이름>()` 정적 함수로 구현한다.

| 상태 | 원본 (`MFx_New_Ver/USER/App/DM_Main_Sq_App.c`) | 쓸 시간 상수 |
|---|---|---|
| `APP_SEQ_SAMPLE_LOAD_WAIT` | 392~481행 | `APP_SAMPLE_LOAD_WAIT_MS` |
| `APP_SEQ_OVER_SAMPLE_CHECK` | 490~544행 | `APP_OVER_SAMPLE_CHECK_MS` |
| `APP_SEQ_LOW_SAMPLE_CHECK` | 545~598행 | `APP_LOW_SAMPLE_CHECK_MS` |
| `APP_SEQ_REACTION_WAIT` | 599~633행 | `APP_REACTION_WAIT_MS` |
| `APP_SEQ_RESULT_SCAN` | 634~764행 | — |
| `APP_SEQ_RESULT_OUT` | 765~797행 | `APP_RESULT_OUT_WAIT_MS` |
| `APP_SEQ_ERROR_WAIT` | 798~850행 | `APP_ERR_RUN_TIME_MS` |

`#if _DEBUG_LCD_SEQ_ONLY` 로 감싸인 블록은 **옮기지 않는다**. `#else` 쪽만 본다.

### 2-2. 블로킹을 상태로 바꾸는 규칙

원본의 19개 대기 지점을 아래 형태로 바꾼다. **이것이 이 작업의 전부다.**

| 원본 | 바꿀 모양 |
|---|---|
| `DM_HW_Drv_SystemSleep_10ms();` | 단계 진입에서 `s_seq.dwStart = HW_Tick_Get();`, 다음 패스에서 `HW_Tick_Elapsed()` 비교 |
| `while ((GetSystemTick() - t0) < X)` | `SEQ_PH_WAIT` 상태 + `HW_Tick_Elapsed(s_seq.dwStart) >= X_MS` |
| `DM_App_Optic_Measure(ch)` (즉시 값 반환) | `APP_EXEC_Measure_StartSingle(ch)` → 다음 패스에 `APP_EXEC_Measure_IsBusy()==0` 확인 → `Optic_GetScaled(ch)` |
| `Sleep_And_CheckStick_250ms(...)` | 아래 2-3의 헬퍼 |

**중요**: 측정은 이제 즉시 값을 주지 않는다. 한 단계에서 여러 채널을 재야 하면
채널 색인을 `Seq_Ctx`에 두고 한 패스에 하나씩 진행한다.
`s_StepStickInsert()`가 그 본보기다.

### 2-3. 추가해도 되는 것

**(1) `Seq_Ctx`에 필드 추가** — 아래 세 배열이 필요하다 (원본 전역변수 대응).

| 원본 | 새 이름 | 크기 |
|---|---|---|
| `gs_awEmptyBand_LowData` | `awEmptyBand` | 4 words |
| `gs_awResultBand_LowData` | `awResultBand` | 4 words |
| `gs_awResult` | `awResult` | 3 words |

밴드 순서는 원본 `BAND_T / BAND_BT / BAND_BC / BAND_C` 를 그대로 쓴다.
채널 대응: T=`OPTIC_CH_T`, BT=`OPTIC_CH_BT`, BC=`OPTIC_CH_BC`, C=`OPTIC_CH_C`.

`s_seq`는 이미 `__near`다. 필드를 늘려도 RAM 배치는 그대로 두면 된다.

**(2) `APP_EXEC_Measure`에 세기 비율 함수 추가**

원본 `DM_Utill.c`의 `CalculateIntensity(피제수, 제수)`를 옮긴다.

```c
uint16_t APP_EXEC_Measure_Intensity(uint16_t wDividend, uint16_t wDivisor);
```

계산식과 0 나눗셈 처리는 원본 그대로. 헤더에 `@note Layer: App (exec).
Blocking: no. ISR: no.` 와 `@retval` 을 붙인다.

**(3) 단계 안에서 쓰는 정적 헬퍼**

`s_SleepAndCheckStick()` 같은 헬퍼는 `static` + `s_` 접두사로 자유롭게 만든다.
스틱 재확인 간격은 `APP_STICK_CHECK_INTERVAL_MS` (6250)를 쓴다.
**250이 아니다.** 이유는 `APP_DATA_Config.h` 주석에 있다.

### 2-4. 추가하면 안 되는 것

| 금지 | 이유 |
|---|---|
| `APP_CTRL_` 파일이 `HW_` 헤더를 include | 규격 §3. 단 `HW_Ret_Code.h`, `HW_Tick_Drive.h`는 이미 쓰고 있으므로 허용 |
| 새 전역 변수 | 상태는 `Seq_Ctx` 하나에 모은다 (규격 §7) |
| `while` 대기, 지연 함수 | 이 작업의 목적 자체 |
| 동작 변경·버그 수정 | 아래 3장 |

## 3. 동작은 바꾸지 않는다

구조만 바꾼다. 눈에 띄는 버그가 보여도 **고치지 말고 그대로 옮긴다.**

이유: 오늘 1번 기기에서 기존 펌웨어와 측정값을 비교할 예정이다.
숫자가 다르게 나왔을 때 "구조 때문인지 고친 것 때문인지" 구분할 수 없게 된다.

발견한 문제는 고치지 말고 `설계문서/작업문서/진행사항/2026-11-03_*.md` 에 목록으로만 남긴다.

## 4. 지켜야 할 규격 조항 (해당분만)

전체 규격은 `Documents/STM8_IAR_Workspace/firmware_layered_coding_v2.0.3.html`.
이 작업에 걸리는 것만 옮기면 아래가 전부다.

| 항목 | 규칙 |
|---|---|
| 이름 | 공개 함수 `APP_CTRL_Sequence_<동사>`, 내부는 `static` + `s_` |
| 상태 | `static Seq_Ctx s_seq` 하나. 흩어진 static 변수 금지 |
| enum | 첫 값 0, 마지막 `_COUNT`, `_t` 접미사 없음 |
| 리터럴 | 부호 없는 값에 소문자 `u`, 32비트면 `uL` |
| 매직 넘버 | 금지. 전부 `APP_DATA_Config.h` 의 이름 있는 상수 |
| 상태 머신 | 모든 상태에 탈출 경로(시간 초과 또는 에러) |
| 시간 비교 | `HW_Tick_Elapsed(start) >= X` (wrap 안전) |
| 주석 | 영문. 섹션 순서 Includes → defines → types → variables → prototypes → private → public |
| 함수 주석 | 공개 함수는 `.h`에 `@brief` `@param` `@note Layer/Blocking/ISR` `@retval` |
