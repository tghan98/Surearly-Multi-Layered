## 2. 분업

| 담당 | 범위 |
|---|---|
| Cowork | App 층 배치 판단, 데이터·실행 층, 제어 층 뼈대 + IDLE·STICK_INSERT |
| 코덱스 | 나머지 7단계 이식 |

지시서: `설계문서/작업문서/코덱스_지시서_시퀀스_7단계.md`

IDLE과 STICK_INSERT를 Cowork가 맡은 이유:
- IDLE은 Halt 진입·복귀 순서가 대기 전류 71 µA를 좌우한다
- STICK_INSERT는 비동기로 바뀐 9회 측정과 맞물린다
- 두 단계가 같은 파일 안의 본보기가 되어, 나머지 7단계는 반복 작업이 된다

코덱스는 플래시 초과를 확인하고 **지시서대로 멈췄다.** 커밋하지 않았다.

## 3. 플래시 한도 초과와 감축

### 3-1. 경과

| 시점 | 필요 | 한도 8,064 B 대비 |
|---|---|---|
| 7단계 이식 직후 | 8,638 B | +574 |
| 최적화 전략 Size | 8,318 B | +254 |
| Loop unrolling 끔 | 8,291 B | +227 |
| Multi-file Compilation | 8,203 B | +139 |
| 슬롯 통계 끔 | 8,163 B | +99 |
| USART 벤더 함수 2개 교체 | **8,053 B** | **−139 (통과)** |

상세와 쓰지 않은 카드는 설계서 §9.

### 3-2. 판단 순서를 한 번 틀렸다

처음에 레지스터 직접 접근(어려움)을 먼저 제안했다가, 사용자 질문을 받고
컴파일러 옵션(공짜)을 건너뛴 것을 발견했다. 위험 없는 것부터 쓰는 순서로 고쳤다.

결과적으로 **위험 없는 조치만으로 475 B**를 줄였고, 낮은 위험 조치는 110 B만
썼다. 높은 위험(깨우기 핀)은 손대지 않았다.

### 3-3. RAM도 한 번 막혔다

패턴: **0페이지 포화** — 8비트 주소로 닿는 256 B 영역에 변수가 다 들어가려다 넘침.

데이터 모델이 `small`이라 모든 변수가 0페이지로 가는데, 0x100~0x2FF 512 B가
비어 있었다. 기존 펌웨어는 RAM 변수가 126 B뿐이라 이 문제를 만나지 않았다.

조치: 프로젝트 전용 링커 설정 `EWSTM8/MFx_Layered.icf`를 만들고,
큰 버퍼 5개를 `__near`로 옮겼다. 스택 바로 아래 64 B는 완충으로 비워 두었다.

## 4. 실기 검증 (1번 기기)

### 4-1. 동작

스틱을 꽂자 **물방울 아이콘이 깜박였다.** 이것으로 아래가 한 번에 확인됐다.

| 확인된 것 |
|---|
| Halt에서 깨어남 — 잠들기·복귀 순서가 맞음 |
| 관문 측정 통과 (원본축 2,600) |
| 삽입 횟수 EEPROM 저장 |
| 사용 횟수 EEPROM 읽기 |
| 초기 측정 9회 완주, 중간 스틱 확인 전부 통과 |
| 양품 범위 검사 통과 (1,500~3,900) |
| 배율 계산 성공 (오차 25 이내) |
| 화면 전환 |

### 4-2. 측정값 — 기존 펌웨어와 비교

브레이크포인트 `APP_CTRL_Sequence.c:311` (`s_GoStep(APP_SEQ_SAMPLE_LOAD_WAIT)`).
초기 측정이 끝나고 다음 단계가 덮어쓰기 전의 마지막 지점이다.

| 채널 | 원본 | 배율 | 배율 적용 |
|---|---|---|---|
| T (CH0) | 3,722 | 32 | 1,191 |
| BT (CH1) | 3,695 | 32 | 1,182 |
| BC (CH2) | 3,698 | 32 | 1,183 |
| C (CH3) | **3,690** | **33** | **1,217** |

**기존 1번 기기 (2026-10-14, 2.89 V)**: 원본 3,664 / 배율 32 / 배율적용 1,172

| 검사 | 기준 | 결과 |
|---|---|---|
| 원본이 정상 범위인가 | 3,541~3,714 | 통과 (CH3 3,690, 기존 대비 +0.7 %) |
| 배율이 기존과 같은가 | 32 | 32~33 |
| 배율 적용값이 목표 안인가 | 1,200 ± 25 | **네 채널 모두 통과** |

검산:
```
3,722 × 32 ÷ 100 = 1,191
3,690 × 33 ÷ 100 = 1,217
```

**"구조만 바꾸고 동작은 그대로"가 숫자로 확인됐다.**

### 4-3. 눈여겨볼 점 — CH3 배율이 경계선에 있다

| 원본 | 계산되는 배율 |
|---|---|
| 3,693 이상 | 32 |
| 3,692 이하 | 33 |

CH3가 3,690이라 경계 바로 아래다. 측정이 몇 카운트만 흔들려도 32와 33을 오간다.
기존 펌웨어도 같은 계산식이므로 동일하게 동작했을 것이다. 결함은 아니지만,
나중에 값이 달라 보일 때 이 경계가 원인일 수 있다.
