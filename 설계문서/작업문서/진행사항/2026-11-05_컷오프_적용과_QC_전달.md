## 2. 판단한 것

이번 주 판단은 두 건이고, 둘 다 설계서에 옮겼다.

| 판단 | 위치 |
|---|---|
| 덤프 필드는 끝에만 붙인다 | 설계서 §7-7 |
| 컷오프가 펌웨어 상수인 것이 구조적 부채 | 설계서 §7-7 끝 |

짧게 다시 적으면 — 컷오프 4바이트를 덤프 **끝**에 붙였다. 앞에 끼우면 뒤 필드가
전부 밀려 기존 CSV와 QC 프로그램 파서가 어긋난다. 길이(249 / 253)로 형식을
구분하고 앞쪽 오프셋은 건드리지 않는다.

## 5. 출하검사 프로그램 개편

QC·생산팀 요청으로 화면을 다시 짰다. 상세는 `설계문서/Test_UI/multi.html`이
그대로 기록이므로 여기엔 요청 출처만 남긴다.

| 요청 | 출처 |
|---|---|
| 각 항목에 1~8 번호 부여 (번호로 소통) | 상사 지시 |
| 적용 컷오프를 버전/LOT 바로 아래 배치 | 상사 지시 |
| 검사 기록을 최신순으로 | QC 회의 |
| 용어 설명 추가 (생산팀 대상) | 생산팀 |

`build_production.py`가 DEV 전용 블록을 떼고 배포본(`multi-production.html`)을
만든다. `Q`(QC 재시작) / `R`(사용횟수 초기화) 명령이 배포본에 남아 있으면
빌드가 실패한다.
