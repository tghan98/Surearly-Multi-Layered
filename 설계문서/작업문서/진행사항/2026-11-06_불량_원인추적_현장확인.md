## 1-3. 수석님 판단 — 센서 편차가 커서 범위가 좁다 — ⚠️ 기각

> "사무실에서 코딩한 거랑 현장에서 다를 수가 많거든. 당연한 거야.
>  양산 들어가면 편차가 엄청 나."

범위를 넓히려면 튜닝 타깃을 낮춰야 한다(1200 → 900 정도)는 판단.
**현장 덤프 21건 중 초기 범위에서 걸린 기록은 0건**이라 조정 근거가 없다.

**숫자 주의** — 수석님은 범위를 "1600~3200"으로 기억하신다.
실제 코드값은 1500~3900(`APP_DATA_Config.h:47~48`), QC 프로그램 `multi.html:452`도 같다.

## 1-4. 타깃을 낮추면 스틱 문턱도 같이 내려야 한다 (설계 메모, 유효)

```
APP_OPTIC_TARGET_LIGHT            1200u   튜닝 목표
APP_OPTIC_STICK_THRESHOLD_SCALED   556u   스틱 유무 문턱
```

556은 타깃 1200을 전제로 한 값이다(비율 0.463). 두 값이 따로 적혀 있어
**타깃만 고치면 조용히 어긋난다** — 묶여 있어야 할 상수의 분리.
지금 타깃을 바꿀 일은 없지만, 바꾼다면 컴파일 시점 계산으로 묶는다(플래시 0 B).

```c
#define APP_OPTIC_STICK_THRESHOLD_SCALED \
    ((uint16_t)((APP_OPTIC_TARGET_LIGHT * 463uL) / 1000uL))
```

| 시험 | 기기 | 결과 |
|---|---|---|

556 양쪽 여유:

```
뺀 스틱 C 266~522  ──[여유 34]──  556  ──[여유 187]──  젖은 스틱 C 743 이상
```

- 젖은 쪽은 넉넉하다. **오늘 불량의 원인이 아니다.**
- 뺀 쪽 여유가 34뿐이다(`151331`의 522). 빈 스틱 C가 556을 넘는 기기는 빼도 "있음"으로 본다.
  스위치를 같이 보면 이 의존이 줄어든다.

**물방울만 표시** = 시료 대기 화면. 시료가 5분 안에 안 들어오면 표시 없이 꺼진다(정상).

### 오전에 556을 의심한 이유 (교훈)

덤프 에러 28건 중 20건이 "스틱 빠짐/실패"였고 그 판정 기준이 556이라 "556 오판"으로 읽었다.
실제로는 스틱이 정말 빠져 있었고 556은 **제대로** 걸렸다.
**에러 기록은 어느 확인에서 걸렸는지만 알려준다. 그 확인이 틀렸는지는 재현 시험으로 본다.**
10-15 커밋(752120b)의 "젖은 스틱 오인" 기록에 끌려간 것도 있다.

## 2-4. 결함 1 — 스틱을 빼면 "시료 도착"으로 오인 (확정)

생산 불량 다수: "빼면 책+물방울 깜빡임이 아니라 **책만** 뜬다."

```
스틱 뺌 → 네 채널 동시에 어두워짐 → T/BT 비가 90% 아래 → "시료 도착" (약 1 s 주기)
→ OVER/LOW SAMPLE CHECK 진입 → 스틱 확인(6.25 s 주기)에서 실패
→ APP_ERR_STICK_FAIL → 책만 고정 표시 (s_ShowError)
```

| 에러 | 언제 | 화면 |
|---|---|---|
| STICK_REMOVE | 시료 도착 **전** | 책 + 물방울 깜빡임 |
| STICK_FAIL | 시료 도착 **후** | 책만 |

- `154047`(불량 접수 기기): 에러 3건 모두 step 3/4 STICK FAIL, 결과밴드 ≈ 410/590/620/480(빈 스틱 값).
- `151331`: 12:57 덤프 후 사람이 뺀 스틱이 같은 형태(363~522)로 기록됨.
- 핵심은 **시료 확인(1 s)이 스틱 확인(6.25 s)보다 먼저 반응**하는 구조다. 556 값을 바꿔도 안 고쳐진다.
- alpha.2는 스위치가 빼는 즉시 알려 이 문제가 없다.

수정 방향(안): 스틱 유지 판정을 스위치 + 광학 동시로. "둘 다 빠짐일 때만 빠짐"으로 해서
스위치 유격도 막고, 시료 도착 판정 직전에 스위치를 확인한다. 스위치 핀 PB1은 이미 입력으로 설정돼 있다.

## 2-5. 결함 2 — 꽂자마자 책 (재현, 원인 미확정)

`152510`(배란, Insert 2): 꽂자마자 책 고정. 새 결과 기록 없음 + Wake Fail ≠ 0
→ 깨어날 때 광학 판정(원본 C < 2600) 실패. **빠르게 꽂아도 3회 연속 재현** → 삽입 속도 문제 아님.

후보: 전지 약화(LED 약함), 깨어난 직후 센서 회로 미안정(10 ms), 스틱.
③에서 전원 불량이 모두 전지였으므로 **전지부터 확인한다.**
스위치 + 광학으로 바꾸면 판정 자체는 통과하지만, 측정값이 정말 낮다면 다음 단계(초기 범위)에서 다시 실패한다.

## 2-6. 기록 버그 — Wake Fail 값이 깨짐 (불량 원인 아님)
