# 2026-11-19 회의: 깨운 뒤에는 버튼(스위치)을 보지 않는다

- 일시: 2026-11-19 (목) 17:15, 51분
- 참석: 김효신 수석, 유호승 수석, QC 이경순 팀장, 한태경
- 원본: `설계문서/작업문서/작업예정/rough_files/버튼보지말자.txt`

## 1. 문제

- 공정검사를 마치고 품질로 넘어간 리더기 12대 중 3대에서 물방울+책 오류(검사오류2, STICK_REMOVE)가 났다. 재검사하면 나왔다 안 나왔다 한다.
- 꽂고 손을 떼면 내부 스위치가 떨어진다. 스틱도 휘어 있는 경우가 있어 랜덤으로 나타난다.
- 지금 FW는 꽂은 직후 튜닝하는 약 1초 동안 스위치만 본다. 이 3대는 그 1초를 못 버틴다.
- 금형 수정은 하지 않을 방침이라 스위치로는 막을 방법이 없다.

## 2. 처음 나온 안 (채택 안 함)

- 빠짐 체크를 아예 없애고 끝까지 진행한 뒤 결과값으로만 판정하는 안이다.
- 채택하지 않은 이유: 물책 오류가 없어지면 설명서의 검사오류2와 맞지 않는다. QC 팀장님은 부사장님 결정 사항이라고 보았다.

## 3. 결론 (김효신 수석 안, 유호승 수석 동의)

| 구간 | 빠짐 판정 | 오류 |
|---|---|---|
| 깨울 때 | 스위치 (지금과 같음) | - |
| 꽂은 뒤 ~ 시료 도착 전 (STICK_INSERT, SAMPLE_LOAD_WAIT) | C 광학값만 본다. 스위치는 안 본다 | 물방울+책 (STICK_REMOVE) |
| T 변화로 시료 도착 판단 후 (스텝이 넘어간 뒤) | 실시간 체크 안 함 | - |
| 3분 반응이 끝날 때 | 3분 동안 값이 낮은 범위에 머물러 있으면 빠진 것으로 판단 | 책 (STICK_FAIL) |

- 시료 도착 전에는 C 자리가 하얀 바닥이다. 그래서 C가 어두워지면 빠짐이고, 발색과 헷갈릴 일이 없다.
- 김효신 수석 관찰: 정상이면 반응 중 약 600까지 내려갔다가 끝나면 700~900으로 다시 올라온다. 빠졌으면 다시 올라오지 않는다. 구분이 되는지는 **실험으로 먼저 확인**한다.
- 설명서는 바꾸지 않는다. "분리되었을 때 나타나는 오류"는 3분 뒤에 떠도 맞다. 바로 뜬다는 문구는 없다.
- 결과적으로 코드는 줄어든다. 버튼 체크가 스텝 체크로 바뀐다.

## 4. 코드에서 바뀌는 곳 (예정)

- `s_RemoveCheck` (`User/03_App/APP_CTRL_Sequence.c`)
  - 스위치 250 ms 창 판정을 없앤다.
  - STICK_INSERT, SAMPLE_LOAD_WAIT에서는 C만으로 판정한다.
  - OVER/LOW_SAMPLE_CHECK, REACTION_WAIT에서는 판정하지 않는다.
- `APP_SW_FAULT_WINDOWS` (11-11 QC 통화로 넣은 접점불량 책 오류): 버튼을 보지 않으므로 삭제 대상이다. **확인 필요.**
- 마지막 판정 (3분 값 변화): 새로 만든다. 기준값은 실험 후 정한다.
- 참고: SAMPLE_LOAD_WAIT 중에는 T/BT를 1초마다 읽는다 (250 ms x 4). C는 빠짐 체크 쪽에서 따로 읽는다.
